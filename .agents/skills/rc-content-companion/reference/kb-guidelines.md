# Knowledge Base (KB) Article Guidelines

## General Principles

RingCentral's Knowledge Base is the collection of support articles about products and services.

KBs should be:
- **Focused**: Specifically concerned with solving users' problems and answering questions
- **Useful**: Consisting of exactly the steps necessary to answer a question or solve a problem
- **Efficient**: As brief as possible in addressing all angles of the subject

Key considerations:
- Focus on the user's experience; put yourself in the reader's position
- Write articles that address users' tasks, not just describe the UI
- Most KBs are customer-facing for a general audience; some target admins, managers, or engineers
- KBs are not marketing vehicles — no promotional or sales copy
- Use plain, clear language, not jargon

## Editing and Writing Rules

1. **Minimal Edits**: Make only essential edits for grammar, punctuation, and spelling. Avoid rewriting unless necessary for clarity.
2. **Clarity and Consistency**: Simplify wording for readability while retaining original meaning. Align tone with RingCentral standards — professional yet conversational.
3. **Error Documentation**: Number each issue. Provide original text, corrected text, and brief explanation.
4. **Respect Formatting**: Treat strikethroughs as confirmed deletions. Yellow highlights are updates — review for accuracy and guideline adherence.
5. **Tone and Accessibility**: Use contractions. Avoid sight-specific terms ("see" → "view" or "access"). Avoid Latin terms ("i.e.", "e.g.") per style guide.
6. **RingCentral Standards**: Use the StyleSheet, Writing Style Guide, and Controlled Vocabulary. Use "Click" for clickable elements and "Select" for dropdowns. Sentence case for headers.
7. **Customization**: Tailor feedback based on writer's requests. Adjust for more detailed revisions when asked.
8. **Content Context**: Use the KB provided as primary reference. Align edits with broader workflow or functionality described.

## KB Categories

### HOW-TO (most common)
Explain how to accomplish a task. Organization strategies:
- By user task (preferred): step-by-step format
- Topically: create, manage, edit, delete
- In UI order: top to bottom, left to right

### INTRODUCTORY
Detail and explain full functionality of a feature. Organized topically or in UI order.

### FAQ
List likely questions and answers.
- Title/H1: product/feature/topic name + "FAQ"
- Each question as H2, answered in normal text below
- For 10+ questions: group under H2 with questions as H3

### TROUBLESHOOTING
Help diagnose and solve problems. List of problems followed by solutions.

### REFERENCE
Settings and protocols for system admins. Highly technical documents.

## Formatting Rules

### Titles
- Sentence case
- When title begins with a verb, use the gerund: "Sending a fax" not "Send a fax"
- Include the product, except when referring to RingEX: "RingCX network requirements" not "Network requirements"

### Intro
- 1-3 sentences describing the article
- Briefly explain the product/feature if not clear
- May link to 1-2 relevant articles

### Table of Contents
- Auto-generated from H2 headings
- If pills are used, TOC won't auto-generate; use jumplinks for 700+ word articles

### Pills
- Button-style components placed under title and intro
- Must have an H2 heading underneath that mirrors the pill content
- Frequently used to separate by access point (Desktop & web app, Mobile, Admin Portal)
- Include an intro sentence before pills
- Format: `[Pill: Desktop & web][Pill: Mobile]`

### Headers
- H headings must be sequential (don't skip H2 to H4)
- H2 and H3 generally start with gerunds
- Troubleshooting articles may use simple present in headings ("Check your network connection")
- Use plural as default in headers

### Notes
- Use singular "Note:" even for multiple notes
- Use bullets for multiple notes
- Bold "Note" in a note box; don't bold "Note" outside a box
- Consider including note information as inline text (users often skip notes)

### External Links
- Find organic opportunities to link related KBs
- Add "Additional resources" section at end if needed
- Use self-descriptive, clear link text (accessibility compliance)
- Link to RingCentral resources first; use external links only when unavailable

### Screenshots
- Most KBs require screenshots
- Use numbered callouts for step-by-step walkthroughs
- Don't use too many — they make articles unnecessarily long

### RingCentral App UI Terms
- **Top bar**
- **Navigation bar**: "In the navigation bar" or "In the left navigation bar"
- **Left panel**: "In the left panel" (not "left navigation panel" or "left-hand navigation bar")
- **Main panel**: Usually internal use only
